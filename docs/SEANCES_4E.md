## 4E-00 : Retour sur le chantier

- **Statut** : ESSENTIELLE
- **Ancrage** : Réel Givors (bandeau « Situation réelle »)
- **Thème dominant** : T1
- **Problématique** : « Quels systèmes techniques permettent de réaliser les transformations que tu observes ? »
- **Objectifs** : réutiliser le même composant technique que 5E-00 avec une scénarisation différente, adaptée au niveau 4e ; recueillir les représentations initiales.
- **Connaissances** : vocabulaire système technique, sous-système (remobilisation).
- **Compétences** : sensibilisation à C1 et C4 (aucune évaluation).
- **Activité** : observation guidée de photographies réelles de Givors, questions orientées système technique plutôt qu’objet isolé.
- **Manipulation** : aucune manipulation technique, observation et questionnement.
- **Trace écrite** : réponse personnelle conservée dans le cahier, reprise en 4E-11.
- **Fiche de cours aménagée** : cadre de réponse court avec amorce de phrase.
- **Évaluation** : diagnostique, sans note.
- **Type d’évaluation** : diagnostique.
- **Barème** : sans objet.
- **Preuves de compétence** : aucune.
- **Aides** : reformulation de la question, exemple d’amorce.
- **Remédiation** : sans objet.
- **Approfondissement** : sans objet.
- **Durées** : rapide 15 · moyen 25 · lent 38 · maximum absolu 40.
- **Critères de réussite** : l’élève a formulé une réponse personnelle écrite dans son cahier.
- **Sources nécessaires** : photographies réelles de Givors (idéalement différentes de celles utilisées en 5E-00 pour montrer une évolution). **Aucune source exploitable disponible à ce jour** (voir `docs/ANALYSE_SPEC.md` § 4).

## 4E-03 : Hydraulique et mouvement

- **Statut** : ESSENTIELLE
- **Ancrage** : Simulation Quartier des Ateliers
- **Thème dominant** : T2
- **Problématique** : « Comment un fluide peut-il faire bouger un bras d’acier ? »
- **Objectifs** : comprendre qualitativement pompe → fluide → distributeur → vérin → mouvement ; faire varier quelques paramètres simples ; expliciter les limites du modèle.
- **Connaissances** : principe qualitatif de la transmission hydraulique.
- **Compétences** : C4, C8.
- **Activité** : simulation pédagogique simplifiée avec un ou deux paramètres réglables (pression, débit) et observation de l’effet sur la vitesse du mouvement.
- **Manipulation / simulation** : simulation qualitative 2D/2,5D ; rubrique « Limites du modèle » explicite (« Cette simulation simplifie notamment le sol, le fluide, les pertes, l’usure, la météo et le comportement réel. »).
- **Trace écrite** : schéma pompe → fluide → distributeur → vérin → mouvement, avec observation de l’effet d’un paramètre.
- **Fiche de cours aménagée** : schéma pré-dessiné, cadre d’observation à compléter.
- **Évaluation** : formative.
- **Type d’évaluation** : simulation guidée + question d’observation.
- **Barème** : sans objet.
- **Preuves de compétence** : preuve formative pour C4 et C8.
- **Aides** : indices sur l’effet attendu d’un paramètre.
- **Remédiation** : simulation avec un seul paramètre variable si échec répété.
- **Approfondissement** : faire varier un second paramètre et comparer.
- **Durées** : rapide 26 · moyen 34 · lent 41 · maximum absolu 45.
- **Critères de réussite** : schéma correctement ordonné et observation cohérente de l’effet du paramètre testé.
- **Sources nécessaires** : aucune donnée réelle indispensable ; valeurs pédagogiques fictives annoncées.

## 4E-05 : Pourquoi l’engin ne fonctionne-t-il plus ?

- **Statut** : ESSENTIELLE
- **Ancrage** : Simulation Quartier des Ateliers
- **Thème dominant** : T2
- **Problématique** : « Comment trouver la cause d’une panne ? »
- **Objectifs** : observer les symptômes, formuler des hypothèses, réaliser des tests, éliminer certaines causes, identifier le dysfonctionnement, proposer une solution.
- **Connaissances** : démarche de diagnostic par élimination.
- **Compétences** : C4, C5.
- **Activité** : scénario de panne avec plusieurs causes possibles, tests simulés à choisir dans un ordre pertinent.
- **Manipulation / simulation** : simulation de diagnostic pas à pas (choix d’un test → résultat → élimination d’une hypothèse).
- **Trace écrite** : tableau symptôme / hypothèses / tests / cause retenue / solution proposée.
- **Fiche de cours aménagée** : tableau pré-structuré à compléter au fil de la mission.
- **Évaluation** : **sommative intermédiaire n° 2**.
- **Type d’évaluation** : diagnostic guidé noté sur la pertinence de la démarche autant que sur la conclusion finale.
- **Barème** : défini dans `.mctkey` (points pour la démarche + points pour la cause identifiée).
- **Preuves de compétence** : preuve sommative pour C4 et C5, contexte « diagnostic de panne ».
- **Aides** : désactivées par défaut pendant la sommative.
- **Remédiation** : reprise du même scénario en formatif après correction, avec indices activés.
- **Approfondissement** : second scénario de panne à résoudre pour les élèves rapides.
- **Durées** : rapide 28 · moyen 35 · lent 42 · maximum absolu 45.
- **Critères de réussite** : démarche d’élimination cohérente et cause finale correctement identifiée.
- **Sources nécessaires** : aucune donnée réelle indispensable.

## 4E-06 : Programmer la sécurité

- **Statut** : ESSENTIELLE
- **Ancrage** : Simulation Quartier des Ateliers
- **Thème dominant** : T3
- **Problématique** : « Peux-tu programmer une sécurité plus complète que celle vue en 5e ? »
- **Objectifs** : introduire progressivement événement, variable, condition, boucle, capteur, action ; modifier, exécuter, observer, corriger.
- **Connaissances** : condition avec alternative (SI... ALORS... SINON...), variable simple.
- **Compétences** : C6, C9.
- **Activité** : environnement de programmation par blocs, tâche guidée avec exemple :

```text
SI distance < seuil
ALORS arrêter
SINON autoriser le déplacement
```

- **Manipulation** : construction ou correction d’un programme (moins de huit blocs), exécution en simulation qualitative, observation, correction.
- **Trace écrite** : recopie du programme final avec légende des blocs.
- **Fiche de cours aménagée** : gabarit de blocs pré-imprimés.
- **Évaluation** : **sommative intermédiaire n° 3**.
- **Type d’évaluation** : programmation notée sur le comportement correct du programme dans plusieurs scénarios de test.
- **Barème** : défini dans `.mctkey`.
- **Preuves de compétence** : preuve sommative pour C6 et C9, contexte « programmation sécurité 4e ».
- **Aides** : désactivées par défaut pendant la sommative.
- **Remédiation** : reprise guidée bloc par bloc en formatif après correction.
- **Approfondissement** : ajouter une variable de vitesse en plus de la distance.
- **Durées** : rapide 28 · moyen 36 · lent 43 · maximum absolu 45.
- **Critères de réussite** : comportement correct du programme dans au moins trois scénarios de test sur quatre.
- **Sources nécessaires** : aucune donnée réelle indispensable ; environnement de programmation interne (voir ÉTAPE 12).

## 4E-08 : Construire un protocole de test

- **Statut** : ESSENTIELLE
- **Ancrage** : Simulation Quartier des Ateliers (protocole expérimental, pas une simple simulation de chantier)
- **Thème dominant** : T3
- **Problématique** : « À quelle distance le capteur détecte-t-il correctement un obstacle ? »
- **Objectifs** : définir les distances à tester, décider d’un protocole simple, réaliser plusieurs essais, répéter les mesures, relever les résultats dans un tableau, comparer les résultats, identifier une zone de détection fiable, proposer un seuil de sécurité, expliquer les limites du test. Faire comprendre explicitement la différence entre simuler, expérimenter, mesurer et valider.
- **Connaissances** : protocole de test, répétabilité, seuil de fiabilité.
- **Compétences** : C8 (principale).
- **Activité** : série d’essais simulés à distances croissantes, avec répétition demandée à chaque distance.
- **Manipulation / simulation** : simulateur de détection paramétrable (distance réglable), résultats affichés essai par essai, pas de résultat global instantané pour forcer la démarche de protocole.
- **Trace écrite** : protocole rédigé, tableau de mesures rempli, conclusion (seuil de sécurité proposé + limites du test).
- **Fiche de cours aménagée** : tableau de mesures pré-structuré (colonnes distance / essai 1 / essai 2 / résultat), cadre de conclusion.
- **Évaluation** : **sommative intermédiaire n° 4**.
- **Type d’évaluation** : protocole de test noté sur la rigueur de la démarche (répétition, tableau, seuil proposé, limites explicitées), pas uniquement sur un résultat chiffré unique.
- **Barème** : défini dans `.mctkey`.
- **Preuves de compétence** : preuve sommative pour C8, contexte « protocole de test capteur ».
- **Aides** : désactivées par défaut pendant la sommative.
- **Remédiation** : reprise du protocole en formatif avec une distance imposée après correction.
- **Approfondissement** : tester un second type de capteur et comparer les seuils obtenus.
- **Durées** : rapide 29 · moyen 37 · lent 43 · maximum absolu 45.
- **Critères de réussite** : au moins trois distances testées avec répétition, tableau correctement rempli, seuil de sécurité proposé et cohérent avec les mesures, limite du test explicitée.
- **Sources nécessaires** : aucune donnée réelle indispensable ; valeurs pédagogiques fictives annoncées pour la portée du capteur simulé.
